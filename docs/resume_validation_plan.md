# 简历项目验证与交付策略

> 状态：`DONE`
> 日期：2026-10-06
> 定位：项目主要作为求职作品和面试讲解材料，不以生产认证或完整 P5 研究项目为目标。

## 1. 当前验证基线

保留现有低成本、离线、可重复的回归测试。当前 `mvn -q clean test` 为 109 项，约 30 秒，已排除真实模型、Testcontainers 和 H4 staging。

这份测试集作为简历项目的工程可信度已经足够：

- 证明主流程、状态契约、Checkpoint、幂等、Reviewer、Policy 和 SSE 核心边界存在。
- 不依赖真实 Key 或公网，适合每次提交前运行。
- 不继续为 DTO getter、简单参数校验或相似失败分支新增重复测试。

## 2. 分层验证预算

| 层级 | 运行频率 | 目标 | 是否阻断日常开发 |
|---|---|---|---|
| 默认离线回归 | 每次提交前 | 主线不回归，当前 109 项 | 是 |
| MySQL 持久化集成 | 修改 Checkpoint、Run、Artifact 时 | 验证真实数据库约束与恢复 | 是 |
| 前端生产构建 | 修改前端或接口时 | 类型检查构建 | 是 |
| Docker Demo 冒烟 | 发布候选或面试前 | 证明一键演示链路 | 是 |
| LiteLLM smoke | 改模型配置时或面试前 | 证明代理、普通调用、流式调用可用 | 否，手工 |
| H4 真实模型 5×2 | 面试前或影响正文/评审批次前 | 已验证一轮：10/10 受控终态、返工与恢复通过 | 否，手工 |
| H4 重复 3 次 | 只有要宣称稳定性时 | 重复性与副作用验证 | 否，可选 |
| 正式 P5 30×3 | 只有要写量化收益时 | 质量、成本、性能、恢复证据 | 否，可选 |

## 3. 不再主动扩展的测试

- 不为每个 DTO 字段或构造器参数单独建测试。
- 不为同一结构化输出解析写大量近似用例。
- 不把所有 Tool、Policy、URL 和重试分支都拆成独立测试类。
- 不把真实模型矩阵放进普通 CI。
- 不为尚未实现的 Memory、Context Compression 或 Sandbox 预建测试。

新增测试只接受两类理由：

1. 防止已经影响主流程的真实回归。
2. 支撑简历中准备写出的具体能力或数字。

## 4. 简历交付优先级

在补测试之前，优先完成：

1. 一个可稳定运行的端到端 Demo。
2. 一张清晰的 Workflow / Harness 架构图和主流程图。
3. 3–5 个真实模型输出样例及对应输入、耗时和限制。
4. README 中的项目定位、关键难点、设计取舍和明确非目标。
5. 面试讲解材料：为什么需要 Checkpoint、幂等、Reviewer 和 Replan，而不是继续增加 Agent。

## 5. 是否继续重型验证

H4 最终收口已完成：两种 Workflow 都是 10/10 受控终态，Reviewer 返工、恢复和幂等检查通过；Harness 延迟约为旧链路 3.3 倍、Token 约为 3.8 倍，但尚未完成同口径 legacy 质量评分。

因此：

- 默认开关继续保持关闭。
- Memory、Context Compression、Docker Sandbox 继续暂缓。
- 正式 P5 不进入当前交付路径。
- 只有准备在简历写“稳定性提升”或“质量/成本量化收益”时，才启动 H4 重复 3 次或正式 P5。
