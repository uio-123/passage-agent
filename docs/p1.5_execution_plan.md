# P1.5 执行文档：去模板化与项目身份整理

## 目标与边界

将项目从原模板标识迁移为 Passage Agent 自有身份：Java 根包为
`com.passage.agent`，Maven 坐标为 `com.passage:passage-agent`。本阶段只处理
命名、展示和工程元数据，不修改数据库表名、HTTP API 路径、配置键、业务流程或
既有数据。

原作者许可已在 `development_log.md` 中记录。本次仅删除当前工作树内的模板归属
文本；不重写 Git 历史，不修改第三方依赖、许可证或既有 commit 作者信息。

## 实施步骤

1. 迁移 `src/main/java` 与 `src/test/java` 下的目录树，并替换所有 Java `package`
   和 `import` 引用；同步 Spring Boot、MyBatis XML 与 springdoc 的扫描字符串。
2. 更新 `pom.xml` 的构件标识和描述；核查 Docker、脚本、CI 与文档中不存在旧坐标。
3. 移除前端页脚的模板站点链接与来源文案，保留中性的产品页脚；同步页面标题、README
   和源码/示例配置/SQL 的作者注释及演示头像链接。
4. 使用全仓检索复核不存在旧根包、模板站点、来源文案或模板标识。仅允许
   `docs/development_log.md` 中为迁移审计保留历史说明。
5. 执行 `git diff --check`、`mvn test`、`mvn test -Ppersistence-integration`，并在
   Docker 可用且环境变量齐全时执行 `docker compose config --quiet` 及健康检查。

## 验收与回滚

- Spring Boot 组件扫描、MyBatis Mapper/XML namespace、springdoc 扫描和测试包名均指向
  新根包。
- Maven 构件可构建，默认测试及持久化集成测试通过；前端可完成生产构建。
- 数据库表、HTTP API 和配置键的差异为空。
- 既有测试账号的密码散列继续使用历史盐值；实现会保留其运行时字节值，但不将其作为
  项目身份或展示文案保留。
- 回滚仅需回退本阶段独立提交；不会触碰 P1 持久化数据或对外 API。

## 已知前置条件

持久化集成测试需要可用 Docker。Docker Compose 启动还要求 `.env` 中具备 LiteLLM 与
Pexels 配置；缺失时只验证静态 Compose 配置并如实记录。
